# SPL 规范 —— 剧本标记语言 Screenplay Language v1.0

SPL 是基于 Markdown 的**编剧专用标记语言**：用最少的语法写出符合行业标准的剧本，可直接渲染为排版规范的剧本 PDF。任何 `.md` 文件只要符合本规范，即可被 `scripts/render_pdf.py` 渲染为可打印剧本，并被 `scripts/validate-spl.py` 校验。

## 1. 设计目标与原则

1. **全程可写**：编剧过程中的大纲、节拍表、场景卡、正文全部可用 SPL 表达，不需要切换工具。
2. **标准对齐**：渲染结果对标好莱坞标准剧本格式（Courier/等宽、场景行、居中角色名、对白缩进、右对齐转场）。
3. **机器可验**：所有元素可被脚本确定性校验，格式问题在交付前被剧本医生拦截。
4. **注释安全**：`%%` 注释不渲染，用于存放内部设计备忘。

## 2. 文件结构

一个 SPL 剧本 = 一个 UTF-8 编码的 Markdown 文件，结构为：

```
YAML frontmatter（元数据，必含 title）
─── 正文（场景标题 / 镜头 / 动作 / 对白 / 转场）
```

### 2.1 YAML 元数据

```yaml
---
title: 肖申克的救赎          # 必填：剧本标题
author: 作者名               # 选填
type: feature                # feature=长片 short=短片 series=剧集 short-drama=短剧
genre: 剧情                  # 选填：类型（见 genre-matrix.md）
runtime: 142分钟             # 选填：总时长，或"10集×45分钟"
logline: 一句话故事          # 选填：见 logline-and-concept.md
controlling-idea: 主控思想   # 选填：麦基式一句话主控思想
structure: 三幕              # 选填：三幕 / 15节拍 / 五诫命
---
```

frontmatter 在渲染时生成**封面页**与**每页页眉**（标题+作者）。缺失必填项 `title` 时校验器报错。

## 3. 块级元素（正文）

### 3.1 场景标题（Scene Heading / Slugline）

```
# INT. 咖啡馆 - 夜
# EXT. 监狱操场 - 黄昏
# INT./EXT. 汽车内 - 日
```

- 语法：`# ` + 内/外景前缀 + `. ` + 地点 + ` - ` + 时间。
- 前缀仅允许：`INT.`、`EXT.`、`INT./EXT.`、`I/E.`、`INT/EXT`。
- 时间建议：日 / 夜 / 黄昏 / 黎明 / 连续。
- 可选场号：行尾 `[数字]`，如 `# INT. 咖啡馆 - 夜 [12]`。场号自动编号时请用连续整数。
- 渲染：左对齐、大写、加粗，与前后留白一空行。
- 校验：前缀、地点、时间三段缺一即报错。

### 3.2 镜头标题（Shot Heading）

```
## 特写 门把手上的指纹
## ANGLE ON 监视器屏幕
## 主观镜头 安迪的视线
```

- 语法：`## ` + 镜头类型 + 内容。表示同一场景内的镜头细分，不新建场景。
- 渲染：左对齐、斜体或普通大写，紧随所属场景。
- 校验：`## ` 必须出现在某个 `# ` 场景之后（不可悬空）。

### 3.3 蒙太奇 / 系列镜头（Montage）

```
## 蒙太奇 越狱准备
1. 安迪在图书馆整理书籍
2. 安迪收集小石块
3. 墙上海报的角落被掀起
```

- 语法：`## 蒙太奇 名称` + 有序列表（`1. ` `2. `）。
- 渲染：列表项逐行渲染为镜头条目，不转为对白。
- 校验：列表项必须跟在 `## 蒙太奇` 后，否则按动作段落处理。

### 3.4 动作 / 描写（Action）

```
安迪推开铁门，走廊尽头的灯光在他脸上扫过。他停下，把帽檐压低。
```

- 语法：普通段落。多个连续段落=多个动作块。
- 规则：只写摄影机拍得到的内容（见 SKILL.md 可拍摄写作）。
- 渲染：左对齐，行宽约 6 英寸。
- 校验：动作段不得以 `（` 开头（那是括号提示）；不得为空。

### 3.5 角色提示（Character Cue）

```
**安迪**
```

- 语法：**独占一行的 `**姓名**`**。姓名建议全大写或统一风格。
- 渲染：居中、大写、加粗，与对白之间留 1 行。
- 校验：角色提示后**必须**跟对白段（允许跨 0-1 个括号提示）。悬空角色提示=报错。

### 3.6 对白（Dialogue）

```
**安迪**
（低声）
你在这里待了多久了？
我在这里待了二十年。这里没有一样东西是真正的。
```

- 语法：角色提示后的段落（可多段）。
- 渲染：居中块，左右各缩进约 2.5 英寸，行宽约 3.5 英寸。
- 校验：对白段不得出现在没有角色提示的地方；对白之间不得插入动作段（换角色用新角色提示）。

### 3.7 括号提示（Parenthetical）

```
（低声）        ← 块级：独立成行，位于对白内
你在这里待了多久了？（停顿） ← 行内：括号跟在台词中间
```

- 块级括号提示：独立成行，渲染为对白上方居中斜体。
- 行内括号：放在台词中，渲染为斜体括号。
- 规则（AAA《故事》：文本/潜台词原理）：括号只用于无法从台词与动作推断的必要语气/动作，**禁止**用括号解释台词真实意图。
- 校验：括号提示只能在有角色提示的上下文内；行内括号不能跨段。

### 3.8 转场（Transition）

```
> CUT TO:
> FADE IN:
> SMASH CUT TO:
> FADE OUT.
```

- 语法：`> ` + 转场命令。常用：`FADE IN:`（剧本开头）、`CUT TO:`、`SMASH CUT TO:`、`DISSOLVE TO:`、`FADE OUT.`（剧本结尾）。
- 渲染：右对齐、大写。
- 校验：`> ` 内容必须是已知转场命令之一（或自定义大写短语）；`FADE OUT.` 后不再有内容。

### 3.9 强制分页（Page Break）

```
---
```

- 语法：独立成行的 `---`（水平线）。
- 注意：文件开头的 `---` 是 YAML 边界；正文中的 `---` 才是分页符。
- 渲染：强制新页。默认每页约 55 行自动分页。

### 3.10 注释（Comment，不渲染）

```
%% 第7场：这里必须埋下安迪的锤子（伏笔1号），结尾回收
```

- 语法：行首 `%% `。
- 渲染：完全忽略（不进 PDF）。用于内部备忘、伏笔登记、待办。

### 3.11 字幕 / 插卡（Title Card，可选）

```
## 字幕 一九六六年
```

- 语法：`## 字幕 内容`。渲染为居中大字（无对白场景时标注时间地点变化）。

## 4. 行内元素

| 语法 | 含义 | 渲染 |
|---|---|---|
| `*斜体*` | 强调（如拟声词、外语） | 斜体 |
| `**粗体**` | 行内强调（区别于独占行的角色提示） | 粗体 |
| `（语气词）` | 行内括号提示 | 斜体括号 |

规则：独占一行的 `**姓名**` 一律按角色提示解析；行内 `**` 一律按强调解析。

## 5. 完整示例（示范全部语法）

```markdown
---
title: 归途
author: 示例作者
type: short
genre: 剧情
runtime: 10分钟
logline: 一个迷路的邮差在暴雪夜把一封四十年前的信送回了它本该到达的地方。
controlling-idea: 真正的抵达不是到达地址，而是被人记得。
structure: 三幕
---

> FADE IN:

# EXT. 雪山公路 - 黄昏 [1]

暴雪。一辆破旧自行车倒在路边，后轮空转。

%% 伏笔登记：自行车是主角父亲的遗物，结尾回收

**老周**
（喘着气）
还有五公里。

# INT. 废弃邮局 - 夜 [2]

墙上挂着褪色的中国地图，红线圈出几十个村子。

## 特写 信封上的地址

收件人：青山村 王秀兰（已故 1976）

**老周**
这封信，走了四十年。

> CUT TO:

## 蒙太奇 山路夜行
1. 老周推车翻过雪坡
2. 手电筒光扫过结冰的河面
3. 远处一点灯火

# EXT. 青山村口 - 深夜 [3]

灯火来自一间亮着灯的老屋。老周在门前站了很久。

**老周**
（轻声）
王秀兰家，是这里吗？

屋内无人应答。门缝里漏出的光，像一只手伸出来。

> FADE OUT.
```

## 6. 渲染标准（对标行业格式）

`scripts/render_pdf.py` 按以下参数渲染（对白/角色/转场的标准定位）：

| 项目 | 标准值 |
|---|---|
| 纸张 | A4 或 Letter |
| 字体 | 等宽：Courier / 中文：Noto Sans SC Medium(500) + Bold(700) 11pt，行高 ≥1.25 倍 |
| 上下边距 | 1 英寸 |
| 左边距 | 1.5 英寸 |
| 右边距 | 1 英寸 |
| 场景标题 | 距左 1.5 英寸，加粗大写 |
| 动作 | 距左 1.5 英寸，行宽 6 英寸 |
| 角色名 | 距左 3.7 英寸处居中，大写加粗 |
| 括号提示 | 角色名下方 1 行，同角色名位置，斜体 |
| 对白 | 距左 2.5 英寸、距右 2.5 英寸的居中块 |
| 转场 | 右对齐 |
| 页脚 | 页码右对齐；页眉为 `标题 · 作者` |
| 封面 | 标题居中大字、作者、类型、时长、Logline |

## 7. 校验与渲染工作流

1. **写作**：按本规范书写正文（第 8 步正文写作强制使用 SPL）。
2. **校验**：`python scripts/validate-spl.py 剧本.md` —— 剧本医生格式检查先于此（内容诊断见 `references/doctor.md`）。
3. **渲染**：`python scripts/render_pdf.py 剧本.md` —— 生成 `剧本.pdf`（同名同目录）。
4. **交付**：把 PDF 交给用户，正文源文件（.md）一并保留以便迭代。

## 8. 常见错误与修法

| 错误 | 症状 | 修法 |
|---|---|---|
| 场景前缀缺失 | `# 咖啡馆 - 夜` | 改为 `# INT. 咖啡馆 - 夜` |
| 角色提示悬空 | `**安迪**` 后无对白 | 补对白，或删去该行 |
| 括号解释意图 | `（他其实很害怕）` | 删除；把害怕写成动作 |
| 对白前插动作 | 角色提示和对白之间夹动作段 | 把动作移到角色提示之前 |
| 心理直述 | "她意识到自己错了" | 改写为可见行为 |
| 信息倾倒 | 角色大段讲解设定 | 拆成冲突中的交换 |
